## 제출 자기소개 초안

저는 Unity 모바일 클라이언트 경험에 AI 에이전트 기반 제작·검수·출시 흐름을 결합해 온 개발자입니다. 비투비커넥트 소속으로 KLP CatchU의 클라이언트 개발과 운영을 맡으며 UI, API 연동, 메모리 문제 분석, 팀 코드 리뷰와 온보딩을 경험했습니다.

개인 프로젝트 Howly Dog는 2026년 6월부터 9월까지 진행해 제 Apple 개발자 계정으로 App Store에 출시했습니다. 게임의 전체 구조와 플레이 흐름은 직접 설계했으며 냥코대전쟁과 캔디팡을 참고해 퍼즐의 방향을 정했습니다. 초기에는 Copilot을 코드 보조와 자문에 활용했고, 이후 Codex Agent가 기능을 구현하고 업데이트하도록 작업 흐름을 바꿨습니다. 에이전트에 코드 검토를 요청한 뒤 직접 플레이해 문제를 찾고 수정을 반복했습니다. 버튼 배치가 코드에서 잘못 수정된 사례, NetworkManager 로딩 처리를 요청마다 통일한 사례, 두 PC 간 커밋 누락으로 작업이 꼬인 사례를 통해 프로젝트 지침(Harness)을 보완했고 같은 요청 누락을 줄였습니다. 반복 해결되지 않는 병목은 직접 찾아 수정하고, UI/UX와 프리팹 배치는 직접 노트북에서 편집해 커밋했습니다.

개발은 Mini PC의 Unity CLI를 중심으로 진행하며 iOS 빌드는 Mini PC에서, Xcode 배포는 MacBook에서 처리합니다. App Store 목업 이미지와 설명 수정도 Codex에 지시해 운영하고, 필요한 인증은 직접 입력합니다. 이 과정에서 AI가 만든 결과의 책임은 개발자에게 있다는 기준으로 구조를 설계하고 직접 플레이와 검수를 이어왔습니다.

Bulldozer Master에서는 이 경험을 바탕으로 빠른 기능 실험과 안정적인 클라이언트 품질을 함께 만들고 싶습니다. 특히 플레이어가 체감하는 메커니즘과 UI 흐름을 먼저 이해하고, 성능 및 유지보수 리스크를 작은 단위로 확인하겠습니다. 실무 게임 프로젝트와 개인 출시 경험의 범위를 구분해 설명하고, 맡은 기능을 끝까지 책임지는 구성원이 되겠습니다.

## 제출용 AI 활용 예시 요약

- **도구/역할:** 초기는 Copilot으로 코드 보조·자문, 이후 Codex Agent에 구현·업데이트 요청, Leonardo AI로 게임 에셋 제작
- **사람이 설계한 것:** 게임 전체 구조/플레이 흐름, UI/UX와 프리팹 배치, 네이밍·주석·코드 간소화 규칙, 기능 우선순위
- **검수 루프:** Codex 코드 검토 요청 → 직접 플레이 → 문제/버그 확인 → 추가 수정 요청 → 반복되지 않는 병목은 직접 분석·수정
- **품질 규칙 예시:** 버튼 시각 변경은 코드가 아니라 prefab에서 수정; NetworkManager 공통 로딩 동작을 각 요청에 일관 적용; PC 간 커밋 규칙 명확화
- **배포:** Mini PC Unity CLI로 개발/빌드, MacBook Xcode로 실제 iOS App Store 배포; 스토어 이미지/설명 변경 지시; 인증은 사용자가 직접 처리
- **에셋:** Leonardo AI 활용
- **한계와 책임:** 코드 대부분을 직접 타이핑한 경험으로 표현하지 않는다. 에이전트 생성 코드의 이해, 변경, 디버깅을 독립적으로 설명하고 과제에서 증명해야 한다.
