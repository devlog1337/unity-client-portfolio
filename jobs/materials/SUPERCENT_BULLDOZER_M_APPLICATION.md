## 자기소개서 초안 — 지원 동기 및 직무 적합성

저는 기능을 구현하는 데서 멈추지 않고, 실제 모바일 환경에서 발생한 문제를 추적해 사용자가 겪는 불편을 줄이는 Unity 클라이언트 개발자입니다. KLP CatchU를 개발·운영하며 UI와 API 연동부터 리소스 관리, 장애 대응까지 경험했고, 개인 프로젝트 Howly Dog를 App Store에 출시하며 하나의 게임을 기획부터 배포까지 완성했습니다.

제가 슈퍼센트에 지원하는 이유는 여러 프로젝트에 참여하며 다양한 게임과 기술적 문제를 경험하고, 개발 역량을 넓힐 수 있는 환경이라고 기대하기 때문입니다. 커리어 초반에 다양한 도전을 통해 역량을 키우고, 깊이 몰입할 프로젝트를 팀과 함께 완성하며 장기적으로 기여하고 싶습니다. Bulldozer M은 모바일 게임의 핵심 시스템을 구현하면서 성능과 플레이 경험을 함께 다룬다는 점에서 제가 쌓아 온 방향과 맞습니다. 실무에서는 상품 이미지가 누적되며 메모리 사용량이 증가하는 현상을 Profiler로 확인했습니다. 기존 캐시 방식이 이미지가 계속 바뀌는 서비스 특성과 맞지 않는다고 판단해 화면 오브젝트와 텍스처의 수명을 연결했습니다. 이어 공유 텍스처가 다른 화면에 영향을 주는 문제도 사용 단위 소유권으로 해결했고, 수정 후 해당 원인의 크래시가 재현되지 않는 것을 확인했습니다.

개인 프로젝트에서는 Copilot과 Codex Agent를 사용해 퍼즐, 바인드 컴포넌트, 팝업 페이지 시스템, 사운드, Firebase DB와 소셜 로그인, 스킨·캐릭터 관리 기능을 순차적으로 구현·업데이트했습니다. 코드 검토를 에이전트에 요청한 뒤 직접 플레이해 버그와 사용성 문제를 찾아 수정 요청을 반복했습니다. 반복 해결되지 않는 병목은 직접 찾아 수정했습니다. 게임 구조와 기능 흐름은 직접 설계했고, 코드 스타일과 프리팹 배치는 직접 확인해 작업 규칙(Harness)에 반영했습니다. Mini PC에서 클라이언트 수정과 서버 코드 대조를 진행하고 MacBook의 원격 Codex 플러그인으로 빌드·배포가 자동으로 이어지도록 구성했습니다. 또한 파트장 역할을 맡아 코드 리뷰와 온보딩, 공통 기준 정리를 수행했습니다. 팀의 속도를 높이려면 구현 기준을 문서화하는 동시에, 기획 변경 빈도와 유지보수 비용에 맞는 단순한 코드를 선택해야 한다는 점을 배웠습니다. Howly Dog에서는 인증, 서버 통신, 마스터 데이터, 광고와 스토어 출시까지 직접 연결했습니다.

실무 경력은 Unity 3년이며 현재 4년차입니다. 공고의 5년 이상 조건에는 미치지 않는다는 점을 알고 있지만, 경력을 과장하지 않고 모바일 클라이언트 운영 경험, 메모리 문제 해결, 리드 및 출시 경험으로 직무 기여 가능성을 보여드리고자 지원합니다. 입사 후에는 게임 시스템의 흐름을 빠르게 파악하고, 안정적인 플레이와 반복 가능한 개발 기반을 만드는 데 기여하겠습니다.
