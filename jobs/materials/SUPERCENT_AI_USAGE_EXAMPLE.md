# AI 활용 사례 — Howly Dog 기획·개발·출시 워크플로우

**지원 직무:** 슈퍼센트 [Bulldozer Master] 클라이언트 개발자(계약직)  
**프로젝트:** Howly Dog · 개인 Unity iOS 게임 · 2026.06 개발 시작 / 2026.09 App Store 출시

## 요약

저는 게임의 구조와 플레이 흐름, UI/UX 판단, 작업 규칙을 직접 설계하고 Copilot·Codex Agent를 활용해 구현과 반복 개선을 진행했습니다. AI가 생성한 코드를 검토 요청하고 직접 플레이해 문제를 찾은 뒤 수정 요청을 반복했으며, 해결되지 않는 병목은 직접 원인을 찾아 수정했습니다. 이 방식으로 기획부터 실제 iOS 배포와 App Store 페이지 관리까지 이어지는 개인 프로젝트 워크플로우를 운영했습니다.

## 역할 구분

### 제가 직접 맡은 일

- 게임 전체 구조와 기능 흐름 설계
- 냥코대전쟁과 캔디팡을 참고한 퍼즐 게임 방향 및 플레이 경험 결정
- UI/UX와 프리팹의 실제 배치·화면 구성 확인 및 노트북에서 직접 수정·커밋
- 에이전트 작업 결과 검토, 직접 플레이, 버그/사용성 문제 재현 및 추가 수정 요청
- 반복 해결되지 않는 병목 원인 탐색 및 직접 수정
- 네이밍 컨벤션, 주석 방식, 코드 간소화/통일, UI 수정 위치 등 프로젝트 규칙 정리
- Apple 개발자 계정에서 필요한 인증을 직접 처리하고 최종 배포 결과 확인

### AI 도구 활용

- **Copilot:** 초기 구현 단계에서 코드 보조 및 기술 자문
- **Codex Agent:** 퍼즐, 바인드 컴포넌트, 팝업 페이지 시스템, 사운드, Firebase DB, 소셜 로그인, 스킨·캐릭터 관리 기능 구현 및 업데이트
- **Codex Agent 검토:** 에이전트에 코드 검토를 요청하고 실행/플레이 과정에서 발견한 문제를 다시 전달해 수정
- **Leonardo AI:** 게임 리소스 제작

코드는 대부분 에이전트가 작성했고 저는 일반적인 수동 코드 작성보다 구조 설계, 요구사항 전달, 검수와 병목 해결에 더 많은 비중을 두었습니다. 직접 코드를 많이 작성했다고 주장하지 않습니다.

## 검수와 규칙 개선 사례

### 1. UI 수정 책임을 프리팹으로 바로잡음

Codex Agent가 버튼의 시각적 배치를 코드에서 수정한 사례가 있었습니다. 화면 배치는 프리팹에서 관리해야 한다고 판단해 해당 규칙을 작업 지침(Harness)에 추가했습니다. 이후 화면 배치와 코드 동작의 책임 경계를 더 분명하게 전달했습니다.

### 2. 네트워크 로딩 표현을 일관되게 적용

NetworkManager에 로딩 처리를 추가하면서 특정 요청에만 적용되지 않도록 모든 요청에서 같은 기준으로 처리해 달라고 요청했습니다. 공통 동작을 기준으로 기능을 적용하도록 Harness 규칙을 갱신했습니다.

### 3. 두 PC에서 발생한 커밋 혼선 방지

Mini PC와 MacBook을 함께 사용하면서 커밋이 누락되거나 잘못 올라가 작업 상태가 꼬이는 문제를 확인했습니다. 기기 간 작업 상태와 커밋 규칙을 Harness에 추가해 작업 흐름을 보완했습니다. 이후 버그 수정 요청이 누락되는 일은 거의 없어졌습니다.

### 4. 반복 해결되지 않는 병목은 직접 조사

에이전트에 수정을 요청했지만 반복적으로 해결되지 않는 병목은 직접 증상과 원인을 살펴 수정했습니다. 구체적인 사례를 면접에서 설명할 수 있도록 문제 상황·원인·직접 바꾼 부분·결과를 함께 정리할 예정입니다.

## 개발 및 출시 환경

- Mini PC에서 Unity CLI로 주 개발과 iOS 빌드를 진행
- MacBook의 Xcode로 실제 iOS 앱 배포
- MacBook의 저장 공간 제약으로 빌드와 배포 환경을 분리
- 필요할 때 인증 정보/비밀번호는 직접 입력하고, 일부 입력은 Chrome Remote Desktop으로 원격 처리
- Codex에 요청해 App Store 목업 이미지 등록과 설명 수정 수행
- UI/UX 및 프리팹은 노트북에서 직접 수정하고 커밋
- 앱은 본인 Apple 개발자 계정으로 App Store에 실제 출시

인증 키의 종류나 비밀값은 이 문서 및 공개 저장소에 기록하지 않습니다.

## 이 방식에서 얻은 기준

- AI에게 큰 목표만 주기보다 수정할 대상과 책임 경계를 분명하게 지정
- 생성 코드 검토만으로 끝내지 않고 직접 실행·플레이하여 실제 동작 확인
- 발견한 에이전트 오류를 일회성 수정으로 끝내지 않고 Harness 규칙에 반영
- 공통 기능은 단일 기준(NetworkManager 로딩 등)으로 여러 사용처에 일관되게 적용
- AI 사용 사실보다 결과물의 구조·품질·배포에 대한 개발자 책임을 우선

## 제출 시 설명

이 사례는 개인 프로젝트에서 AI 도구와 원격 실행 환경을 활용한 경험입니다. 현 직장에서 AI를 같은 방식으로 사용했다고 주장하지 않습니다. AI가 작성한 코드의 세부 동작, 제가 직접 정한 게임 규칙 및 시스템 경계, 직접 해결한 병목 사례는 기술 인터뷰와 과제에서 설명할 수 있도록 준비합니다.
