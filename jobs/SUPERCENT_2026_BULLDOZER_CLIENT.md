## 4. 합격 전략

### 포지셔닝 초안

“모바일 Unity 클라이언트를 제품 출시와 운영까지 연결해 온 개발자입니다. 성능·메모리·UI 입력처럼 사용자 체감에 직접 연결되는 문제를 원인부터 해결하고, 개인 게임 출시와 리드 경험으로 실행과 결과를 책임집니다.”

최신 이력서와 실제 사례로 검증하고, 수치가 없으면 만들어내지 않는다.

### 실행 트랙

1. **공고 요건 매핑:** 상세 원문을 확보한 뒤 필수/우대 항목별로 경력 근거, 포트폴리오 링크, 부족한 점을 기록한다.
2. **빠른 지원:** 마감 10/31 전에 이력서·경력기술서·포트폴리오를 직무에 맞춰 제출한다. 아직 지원 전이다. 공고 경력 기준은 5년 이상으로 확인됐고 후보자 본인 설명은 Unity 경력 3년이므로, 기준과 차이가 있더라도 실제 업무 범위·리드 경험·출시 성과를 근거로 지원을 시도한다. 이력서 연차는 사실대로 쓰고, 지원서에서 경력을 부풀리지 않는다.
3. **포트폴리오 증거:** 기존 샘플을 우선 다듬어 문제, 선택 이유, 대안, 실패 케이스, 검증 방법을 설명한다. 성능 사례는 재현 조건과 전후 수치를 확보한다.
4. **리드/출시 사례:** 팀 규모, 본인의 책임, 의사결정, 협업, 일정/품질 개선 결과를 STAR 형식으로 준비한다. Howly Dog 출시 경험도 본인 기여 범위를 분명히 한다.
5. **기술 면접:** C#과 Unity 생명주기, GC/메모리, 비동기·Coroutine, 모바일 성능, 리소스 소유권, UI 입력, 네트워크 실패/재시도, 빌드·배포를 사례 중심으로 설명한다.
6. **회사의 장기 목표:** 현재 공고 결과와 무관하게 주 1회 슈퍼센트 공식 채용 페이지 및 관련 클라이언트 공고를 확인하고, 적합한 후속 공고에 지원한다.
7. **공개 범위:** 회사/게임의 비공개 코드·아트·레벨·데이터를 복제하거나 공개하지 않는다. 독립 구현과 공개 가능한 사례만 사용한다.

### 포트폴리오 보강 후보

새 프로젝트를 무리하게 늘리기보다 기존 Unity Client Portfolio를 강화한다. 공고 상세를 확인한 뒤 우선순위를 정한다.

- 메모리/성능: Profiler 근거, 전후 수치, 재현 과정, 부작용
- 리소스 수명: Texture Lease 설계, 공유 소유권, 해제·오류 처리
- 게임플레이 샘플: 독립적인 캐주얼 모바일 프로토타입의 입력/상태/UI/재시작 흐름
- 각 샘플에 실행 방법, 설계 선택, 대안, 검증 결과 기록
- Bulldozer M의 비공개 구현·콘텐츠를 추측하거나 모사하지 않음
